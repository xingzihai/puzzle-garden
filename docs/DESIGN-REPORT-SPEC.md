# 建筑设计报告规范（交互层 → 构建层）

> 状态：规范草案，2026-10-19。与 `docs/archive/INTERACTION-AGENT-PLAN.md`（历史规划）配套。
> 目的：规定用户交互 agent 交给构建 agent 的“设计报告”必须包含什么、写到什么深度、如何验收。
> 原则：报告不是散文，也不是聊天记录摘要；它是**唯一设计依据**，构建 agent 不再自行重做方案。
> 示例见 [`examples/tea-house-design-report.md`](./examples/tea-house-design-report.md)：一份小体量茶室的 0.1 草案，用于对照报告深度，不是已确认方案。

## 1. 报告的地位

```text
用户需求
  → RequirementGraph（需求、来源、歧义、矛盾、决策）
  → DesignScheme（场地、空间、构件、门窗、结构、屋面、材质、家具、细部）
  → 设计报告（人可读，构建 agent 的施工依据）
  → BuildBrief / BuildSpec / gates（机器可读，构建与验收）
  → 构建 agent
```

- 用户确认的是 `DesignScheme` 的一个版本；设计报告由该版本生成，不手工另写。
- 构建 agent 可以解决施工构造、局部装饰与做法细节；不得改变主要布局、房间用途 / 数量、外部尺寸、层高、入口、主要材质、屋顶形式、用户点名细节。
- 报告中的每个数字必须来自 `DesignScheme`；同一数字只出现一次，其他位置引用表格。
- 报告必须区分：用户原话、代理建议、默认假设、用户确认、未决问题、能力限制。

## 2. 质量门槛

一份可交给构建层的报告，至少满足：

1. **可读**：用户能在 10 分钟内看懂“这是什么建筑、怎么用、长什么样、为什么这样”。
2. **可建**：所有主要空间有尺寸、标高、边界、入口与连接；门窗、楼梯、屋面、结构有做法。
3. **可核对**：每个 must 都有验收方法；关键尺寸、数量、路线能在图上或测量里核对。
4. **一致**：面积、层高、标高、开间、门窗、家具、材料之间不矛盾。
5. **完整**：室内、外观、场地、家具、楼层、细部都在范围内，不能只做空壳。
6. **诚实**：当前 World API / 渲染 / 分析做不到的，写明限制与替代，不假装可交付。
7. **克制**：小体量不靠放大体量、堆尖塔、堆装饰；重点在比例、开间、檐口、材质、门槛、家具与光线。

## 3. 报告结构

建议固定为以下章节；可根据项目裁剪，但 1、2、3、4、5、6、8、9、13 不建议省略。

### 0. 一页摘要

- 项目名、版本、日期、状态（草案 / 待确认 / 已确认 / 构建中）。
- 一句话概念。
- 关键指标表：场地、占地、总建筑面积、层数、最高点、主要空间数、实心方块估算、预算。
- 用户确认项、代理假设、未决问题、能力限制各一行。
- 一张主视角图 / 轴测图（有则放）。

### 1. 项目理解与需求

- **用户原话**：保留关键原句，不只写摘要。
- **需求表**：

| id     | 需求         | 来源     | 优先级 | 状态      | 影响               |
| ------ | ------------ | -------- | ------ | --------- | ------------------ |
| req-01 | 能看稻田     | 用户原话 | must   | confirmed | 朝向 / 开口 / 平台 |
| req-02 | 室内坐 10 人 | 用户原话 | must   | confirmed | 面积 / 家具        |
| req-03 | 日式感觉     | 用户原话 | should | confirmed | 材料 / 屋面 / 檐下 |

- **关键澄清**：问了什么、用户怎么答、为什么问。
- **代理建议 / 默认值**：明确标 `proposed` / `assumed`，不能冒充用户要求。
- **矛盾与取舍**：列出互斥要求、选择、影响。
- **能力边界**：当前不支持的、替代方案、需要用户确认的。

### 2. 场地分析

- 场地尺寸、朝向、坡度、退界、周边建筑 / 道路 / 景观。
- 日照、主导风、雨水、噪声、视线、隐私。
- 入口选择、人车流线、室外分区、停车 / 服务（如适用）。
- 总平面坐标表：场地边界、建筑占地、入口、铺装、院墙、植物、室外家具。
- 一句结论：建筑如何回应场地。

### 3. 设计概念

- 概念叙述（不超过 300 字）：为什么是这个体量 / 平面 / 屋面 / 材料。
- 三个关键词（如“檐下 / 框景 / 木石”）。
- 概念如何对应需求表中的 must / should。
- 不写空泛的“现代、自然、融合”；每条要能落到空间或构件。

### 4. 功能与面积

- 面积表：

| 空间        | 数量 | 面积  | 楼层 | 人数 | 净高  | 相邻 / 分离     | 采光 | 备注   |
| ----------- | ---- | ----- | ---- | ---- | ----- | --------------- | ---- | ------ |
| 主茶室      | 1    | 32 m² | F1   | 10   | 3.2 m | 入口 / 檐下平台 | 南向 | 主空间 |
| 柜台 / 储物 | 1    | 8 m²  | F1   | 2    | 2.7 m | 主茶室          | 侧窗 | 服务   |

- 总面积、净面积、交通面积、室外平台面积。
- 邻接关系图（文字或简单矩阵）：必须相邻 / 可相邻 / 必须分离。
- 公共 / 私密 / 服务分区；入口序列；后勤 / 储物 / 卫生间。
- 面积与方块预算的对应关系。

### 5. 平面设计

- 每层一张带尺寸的平面（坐标表或图示）。
- 墙：外墙 / 内墙 / 厚度 / 材料 / 高度。
- 门窗：编号、所在墙、位置、宽 / 高 / 窗台 / 过梁、开向、框 / 玻璃。
- 楼梯：位置、类型、梯段、踏步、平台、净空、连接的两个标高。
- 家具：固定家具与活动家具分区，尺寸、朝向、与动线的关系。
- 入口序列：室外 → 门槛 → 门厅 / 玄关 → 主空间；视线焦点。
- 动线：主要 / 次要 / 服务；净宽；不穿越私密空间。
- 关键坐标表：每个空间 `[x0,x1) × [z0,z1)`、楼面标高。
- 用户看图时能指认：入口、主空间、柜台 / 座位、楼梯、卫生间、室外平台。

### 6. 标高与剖面

- 标高表：

| 标高  | 楼面        | 层高 | 净高 | 用途        |
| ----- | ----------- | ---- | ---- | ----------- |
| ±0.00 | 室外地面    | —    | —    | 场地        |
| +0.15 | 台基 / 入口 | 0.15 | —    | 门槛        |
| +0.45 | F1          | 3.6  | 3.2  | 主空间      |
| +4.05 | F2          | 3.2  | 2.8  | 阁楼 / 储物 |

- 关键剖面：入口、楼梯、挑空、屋面与墙交接、檐口。
- 屋面坡度、屋脊、檐口、天沟 / 雨水口；结构与净高的关系。
- 楼梯净空、门洞高度、家具与窗台高度。

### 7. 结构

- 结构体系：墙承重 / 框架 / 混合；材料（石、木、钢、混凝土）。
- 柱网 / 墙轴线；跨度；楼板厚度；悬挑；屋面支撑。
- 小建筑合理跨度（启发式）：
  - 木梁 4–6 m；钢梁 6–12 m；混凝土梁 6–9 m；石墙承重 4–6 m。
  - 悬挑建议 ≤ 1.5–2 m；超过时加柱 / 斜撑 / 拉杆。
- 结构可见性：哪些暴露、哪些包在墙内；节点怎么收。
- 与设备 / 排水 / 烟囱的关系。
- 明确“本报告是设计辅助，不是结构计算”。

### 8. 外观与立面

- 体量策略：主次、退台、檐口线、屋脊线、天际线重点（0–3 个）。
- 比例：开间数、开间宽度、墙高 / 檐高、窗墙比。
- 每个立面一张分层表：

| 立面 | 基座      | 墙身 | 腰线 / 檐口   | 窗             | 门           | 顶部 / 屋脊 | 材质         |
| ---- | --------- | ---- | ------------- | -------------- | ------------ | ----------- | ------------ |
| 南   | 深石 1 格 | 木墙 | 浅石外挑 1 格 | 3 樘，窗台 0.9 | 主门 1.2×2.2 | 深瓦屋脊    | 石 / 木 / 瓦 |

- 材料表：

| 部位 | 方块             | 明度档 | 质感 / 用途 | 备注      |
| ---- | ---------------- | ------ | ----------- | --------- |
| 基座 | deepslate_bricks | 深     | 石基        | 外凸 1 格 |
| 墙身 | spruce_planks    | 中     | 木墙        | 竖向      |
| 窗框 | calcite          | 浅     | 石框        | 外凸 1 格 |
| 屋面 | deepslate_tiles  | 最深   | 瓦          | 屋脊换色  |

- 屋面：形式、坡度、出檐、檐口收边、屋脊、排水、烟囱 / 天窗。
- 细部：窗框、窗台、门框、门槛、雨棚、腰线、栏杆、灯具、雨水管。
- 明确哪些是结构必需、哪些是装饰；装饰至少重复 3 处才加。

### 9. 室内设计

室内与外观同等重要；不能只做空壳。

- 空间序列：入口 → 过渡 → 主空间 → 次空间 → 楼梯 / 后门。
- 每个主要房间：
  - 功能、人数、家具区、固定家具、活动家具。
  - 采光 / 通风 / 灯具 / 视线焦点。
  - 墙面 / 地面 / 顶面材料；与外墙材料的关系。
- 家具表：

| 家具 | 位置   | 尺寸    | 做法          | 朝向     | 与动线关系    |
| ---- | ------ | ------- | ------------- | -------- | ------------- |
| 长凳 | 南窗下 | 3×1×0.5 | slab + stairs | 面向稻田 | 留 1.2 m 通道 |
| 书架 | 北墙   | 3×1×2   | bookshelf     | 面向室内 | 不挡门        |

- 固定家具优先：长凳、书架、柜台、桌、床、储物、壁龛、窗座。
- 家具尺度：桌面约 1 m、座面 0.5–1 m、柜台 1–1.1 m、床 2×1 格。
- 动线：门内 1.5 m、楼梯口 1.2 m 净空；主要通道 ≥1 m。
- 室内视线：进门焦点；主窗不对实墙；用室内窗 / 栏杆 / 门洞引光。
- 采光：主要房间至少一扇外窗；进深 >6 m 加室内窗 / 天窗 / 灯。
- 室内材料与外观的连续性：木、石、白墙、织物；不要外观一套、室内另一套。

### 10. 细部设计

按部位列做法、数量、位置、材料、常见错误：

- 窗：框、台、楣、内窗套；同立面窗顶 / 窗台对齐。
- 门：框、门槛、门头 / 雨棚、开向、双开 / 单开。
- 檐口：外挑、收边、转角、滴水。
- 屋脊：压顶、换色、收头。
- 栏杆：高度、端头、转角、开口。
- 排水：天沟、雨水口、落水管。
- 灯具：入口、门廊、楼梯、桌面；chain / lantern。
- 铺装：入口、室内、室外；收边与高差。
- 家具：长凳、书架、柜台、床、桌、储物。

每个细部写清：

- 用哪些方块 / 构件；
- 带方向方块的状态（facing / half / hinge / open / axis / shape / type）；
- 与相邻构件的关系（贴墙、外凸、收口、避让）；
- 数量与重复规律；
- 常见失败与自查方法。

### 11. 场地与景观

- 入口铺装、台阶、门槛、无障碍（如适用）。
- 院墙 / 围栏 / 门楼；与建筑的关系。
- 植物、树池、草地、水景（克制，不大面积扩展）。
- 室外家具、灯具、标识。
- 排水、坡度、雨水去向。
- 与建筑视线 / 隐私的关系。

### 12. 建造顺序

建议按以下顺序，写清每步用什么构件、挂什么锚点、检查什么：

1. 场地与台基：plinth / paving / steps。
2. 结构：walls / colonnade / floorPlate / stair。
3. 屋面：roof / 檐口 / 屋脊。
4. 门窗：opening / frame / fill。
5. 楼梯与楼层：stair / floorPlate / rail。
6. 室内：隔墙 / 家具 / 灯具 / 铺装。
7. 立面细部：窗框 / 窗台 / 腰线 / 檐口。
8. 场地收尾：铺装 / 植物 / 室外家具。
9. 自查：`check_code` 测量 + `view_building` 多视角。

### 13. 验收清单

逐条列出 must 和关键 should：

| id     | 要求           | 验收方法          | 目标                    |
| ------ | -------------- | ----------------- | ----------------------- |
| req-01 | 南向能看到稻田 | 南立面 / 入口视角 | 主窗 / 平台朝南，无遮挡 |
| req-02 | 室内坐 10 人   | 平面家具表 + 视角 | ≥10 座，通道 ≥1 m       |
| req-03 | 大屋檐         | 剖面 / 侧视       | 外挑 1.2–2.0 m，不压窗  |

- 机械可核对：尺寸、面积、门窗数、楼梯可达、悬空、预算。
- 视觉可核对：比例、立面节奏、材质层次、檐口、室内氛围。
- 明确“未校准”的审美项，不冒充机械判据。

### 14. 自由发挥范围与冲突处理

- **不可改**：主要布局、房间用途 / 数量、外部尺寸、层高、入口、主要材质、屋顶形式、用户点名细节。
- **可发挥**：构造做法、局部装饰、铺装图案、灯具、家具细节、植物配置（在不遮挡主体时）。
- **遇到冲突**：停止并报告“涉及哪项要求、具体位置 / 原因、可选调整、影响”，不要自行改方案。
- **交付说明**：构建完成后返回实际采用的方案版本、偏离项、未满足项与证据。

### 15. 附录

- 坐标总表（场地、建筑、空间、门窗、楼梯、家具）。
- 材料表 / 方块状态表。
- 参考图：总平面、各层平面、关键剖面、立面、轴测、室内视角。
- 需求来源与版本记录。

## 4. 写作规则

1. **先结论，后论证**：每节开头一句话结论，再给表格 / 说明。
2. **数字表格化**：尺寸、面积、标高、门窗、家具、材料尽量用表。
3. **不重复**：同一数字只在主表出现；其他位置引用表名。
4. **可指认**：用户能在图上指出每个 must；不能指认的写成偏好。
5. **来源标注**：用户 / 代理建议 / 默认 / 确认 / 未决。
6. **能力诚实**：不支持的写限制与替代；不把“画出来”当成“能交付”。
7. **克制**：小体量不堆装饰；每个装饰有结构理由或重复规律。
8. **室内同等**：不能只写外观；主要空间必须有家具、光线、材料与动线。
9. **长度控制**：默认 6k–12k 中文字符；复杂项目可到 18k；不靠空话凑长度。
10. **版本**：每次修改更新 `revision`，保留旧版本；构建绑定明确版本。

## 5. 与 BuildBrief 的关系

设计报告是**人可读**的主文档；`BuildBrief` 是同一方案的机器视图：

- `design.md`：本规范生成的设计报告。
- `build-task.md`：给构建 agent 的四节题面（需求 / 禁项 / 场地尺寸与建造要求 / 验收与自由范围）。
- `build-spec.json`：坐标、空间、门窗、路线、数量、预算、禁项。
- `gates.json`：现有 `--gates` 能表达的门槛。
- `reference/`：总平面、各层平面、剖面、立面、轴测、室内视角。

`build-task.md` 不是设计报告的压缩版，而是**施工指令版**：只保留构建 agent 需要的信息，去掉讨论过程、备选方案和重复解释。

## 6. 首版验收

- 报告能被用户读懂，能指认主要空间、入口、楼梯、家具、外观重点。
- 构建 agent 读完后不需要重新问布局；主要尺寸、门窗、楼梯、屋面、材质、室内家具齐全。
- `brief/lint.ts` 能检查：must 覆盖、数字一致、引用完整、预算、禁项、能力边界。
- 至少 2 个试点方案由人工评审，确认“这就是我想让交互 agent 产出的深度”。
