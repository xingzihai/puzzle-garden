# 交互层试点题库

> 用途：测试用户交互 agent 的语义理解、澄清、建筑方案设计与构建简报生成；不是构建层题面，也不含模型成品。
> 每份文件只给“用户原话 + 场景 + 评阅关注点”。交互 agent 应自己完成需求抽取、关键提问、方案设计和报告，不应要求用户写结构化题面。

## 使用方式

1. 把 `user-brief.md` 的内容作为用户输入交给交互 agent。
2. 记录：它问了什么、哪些默认假设、最终方案范围、是否触发能力边界、是否要求用户做专业设计。
3. 方案确认后，用 `compileBuildBrief` 生成 `build-task.md` / `build-spec.json` / `gates.json`。
4. 评阅重点见每份文件末尾的“评阅关注点”。

## 评阅原则

- 用户负责偏好与重要取舍；agent 负责设计、计算和解决空间问题。
- 不要求用户逐格设计，也不把用户原话直接当施工图。
- 代理建议、默认值、用户确认必须分开记录。
- 室内、家具、楼层与细部必须进入方案；不能只做外观空壳。
- 当前能力边界要提前说明，不能到构建失败才暴露。
- 不把“精致”做成缩小版巨构；小体量靠比例、开间、檐口、材质、家具与光线。
